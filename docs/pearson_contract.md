# Pearson similarity kernel — frozen mathematical contract

Version 1.0 — frozen 2026-08-26. Any change to this document is a breaking
change and requires regenerating all fixtures and golden results.

This contract is derived from `item_pearson_similarity` /
`user_pearson_similarity` in `spark_pipeline/cf_train.py` (the maintained
copy of the INF553 HW3 `task3train.py`) and is the single normative
reference for every backend: Python, serial C++, OpenMP, CUDA, MPI, NCCL.

## 1. Generic problem

The kernel operates on **entity pairs over a common rating dimension**:

| Instantiation | Entity      | Rating dimension |
| ------------- | ----------- | ---------------- |
| item-item CF  | business    | user             |
| user-user CF  | user        | business         |

Input: for each entity `e`, a rating vector `R_e : dim -> double`.
For a candidate pair `(i, j)`: let `D = keys(R_i) ∩ keys(R_j)` (the
co-rated dimensions), `n = |D|`, `x_d = R_i[d]`, `y_d = R_j[d]` for `d ∈ D`.

## 2. Policies

| Policy               | Rule                                                            |
| -------------------- | --------------------------------------------------------------- |
| Minimum overlap      | Pairs with `n < 3` are not candidates and are never evaluated.   |
| Missing data         | Intersection only; ratings outside `D` are ignored entirely.     |
| Centering            | Pair-local means over `D` only (not global entity means).        |
| Zero variance        | If either centered sum of squares is 0, similarity is 0.         |
| Zero numerator       | If the centered cross-sum is 0, similarity is 0.                 |
| Output filter        | Emit the pair iff `sim > EPS`, `EPS = 1e-14` (see §5).           |
| Precision            | IEEE-754 double (binary64) for all accumulation and finalization.|
| Duplicate ratings    | See §4. Resolved before the kernel; kernel input has unique keys.|
| Pair ordering        | Canonical order: `id_i < id_j` lexicographically by original     |
|                      | string ID (bytewise, as Python `<` on str). Exported integer IDs |
|                      | are assigned in sorted string order, so `int_i < int_j` too.     |

## 3. Formulas

Reference (two-pass, as written in `cf_train.py`):

```
x̄ = (Σ_d x_d) / n          ȳ = (Σ_d y_d) / n
num   = Σ_d (x_d − x̄)(y_d − ȳ)
den   = sqrt(Σ_d (x_d − x̄)²) · sqrt(Σ_d (y_d − ȳ)²)
sim   = 0                      if num == 0 or den == 0
      = num / den              otherwise
```

Sufficient-statistics form (what parallel backends accumulate; additive
across any partition of `D`, which is what makes MPI_Allreduce / NCCL
AllReduce valid):

```
S = (n, Σx, Σy, Σx², Σy², Σxy)                    -- six doubles per pair
num = n·Σxy − Σx·Σy
vx  = n·Σx² − (Σx)²
vy  = n·Σy² − (Σy)²
sim = 0                        if num == 0 or vx <= 0 or vy <= 0
    = num / sqrt(vx · vy)      otherwise
```

The two forms are algebraically identical (both equal `n²·cov` up to the
same factor); they differ in floating-point rounding by O(1e-15) on
realistic ratings (1–5 stars, n up to a few hundred). This is covered by
the tolerance in §5. The **serial C++ oracle uses the sufficient-statistics
form**, since that is the form every parallel backend must reproduce.

## 4. Duplicate-rating policy

`train_review.json` contains multiple reviews for 15,907 (user, business)
pairs (up to 6). The original Spark code resolves them by dict overwrite in
concatenation order, which for a fixed input file means **the last review in
file line order wins**. The fixture exporter applies exactly this rule, so
kernel input always has unique (entity, dimension) keys. Backends never see
duplicates.

## 5. Tolerances, EPS, and comparison protocol

Measured facts (see `spark_pipeline/README.md`, reproduction check): two
runs of the same Spark code on the same data agree to 7.8e-16 on common
pairs, but 97 of ~557k pairs flip across the `sim > 0` boundary because
their true similarity is 0 and summation order produces ±1e-16.

Therefore:

- `EPS = 1e-14`: the emission filter is `sim > EPS`. Any |sim| ≤ EPS is
  treated as "no correlation" and never emitted.
- `TOL = 1e-12`: two backends agree on a pair iff `|sim_a − sim_b| ≤ TOL`.
- Set comparison: backend outputs are compared as maps pair→sim over the
  candidate list. A pair may appear in one output and not the other only if
  both computed values lie within `TOL` of `EPS` (boundary band); anything
  else is a correctness failure.
- Golden fixtures store `sim` for **every** candidate pair (no sign filter),
  so value comparison never depends on set membership.

## 6. Candidate provenance (fixed upstream, never recomputed natively)

- **Item-item**: all unordered pairs of businesses that each have ≥ 3
  ratings and whose co-rater count `n ≥ 3`. Generated by the exporter
  (cartesian + overlap filter, same as `cf_train.py item_based`).
- **User-user**: pairs surviving MinHash/LSH (Jaccard ≥ 0.01 on rated
  business sets) with `n ≥ 3` co-rated businesses, as in
  `cf_train.py user_based`, computed with **deterministic** ID maps (IDs
  sorted before index assignment; the archived run used nondeterministic
  `distinct().collect()` order, so the exported user-user candidate set is
  self-consistent rather than byte-identical to the archived model).

Backends receive the candidate list as data and must evaluate exactly those
pairs — no backend generates or prunes candidates.

## 7. Hand-computed microcases

Machine-readable in `data/fixtures/microcases.json`; validated by
`tools/pearson_reference.py` (pure Python, no Spark) and by every native
backend's unit tests. Cases:

| Case              | Design                                   | Expected                    |
| ----------------- | ---------------------------------------- | --------------------------- |
| identical         | x = y, n = 3                             | sim = +1, emitted           |
| inverse           | y reverses x, n = 3                      | sim = −1, not emitted       |
| one_overlap       | n = 1                                    | below overlap, not a candidate |
| no_overlap        | n = 0                                    | not a candidate             |
| two_overlap       | n = 2, perfectly correlated              | below overlap, not a candidate |
| zero_variance     | x constant on D, n = 3                   | sim = 0, not emitted        |
| orthogonal        | centered vectors orthogonal, n = 3       | sim = 0 (zero numerator), not emitted |
| fractional        | n = 3, sim = 2/√7                        | 0.7559289460184544, emitted |
| intersection_only | fractional + extra non-common ratings    | identical to fractional     |

## 8. Correctness ladder (gates, in order)

1. Reference implementation passes all microcases (both formula forms).
2. Exporter golden sims match the archived Spark model on emitted pairs
   within TOL (modulo the EPS boundary band).
3. Serial C++ matches golden fixtures within TOL.
4. Every parallel backend matches serial C++ within TOL at all
   thread/rank/GPU/chunk counts (partition invariance).
5. Performance measurements begin only after gates 1–4 pass.
